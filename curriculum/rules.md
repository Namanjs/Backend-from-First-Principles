# Rules

## Mission

Reach mid-to-senior backend engineering interview readiness in 10 weeks.

## Primary Standard

Do not optimize for "covered many topics."

Optimize for:

- explaining backend behavior from first principles
- understanding WHY before HOW
- building systems you can defend in an architecture review
- debugging failures from reasoning, not guessing
- knowing tradeoffs, not just patterns

## Weekly Pass Criteria

You pass a topic only if all of these are true:

1. You can explain the mechanism, not just the definition.
2. You can answer follow-up questions without collapsing into memorized phrases.
3. You can implement the practical exercises with deliberate design choices.
4. You can justify the tradeoffs in your implementation.
5. You can identify when this concept is the WRONG choice, not just the right one.

## Study Rules

- No fake confidence.
- No "I know this" without being able to explain it cold.
- No skipping exercises because the theory felt clear.
- No moving ahead if the current layer is weak.
- No cargo-culting libraries without understanding what problem they solve.
- Read error messages before Googling.
- Read official docs before tutorials.

## Code Standards

- Prefer clear naming and small modules.
- Handle errors deliberately, not generically.
- Validate input explicitly.
- Keep secrets in environment variables.
- Write tests for behavior that matters.
- Be able to explain every dependency in your package.json.

## The Shrink-Struggle-Peek-Rebuild Method

For every exercise:

1. Shrink the problem until the first step is obvious.
2. Struggle for 25-30 minutes before looking anything up.
3. Peek at the smallest possible hint — not the whole solution.
4. Close the tab and rebuild from understanding.
5. Expand one layer at a time.

The first version should be embarrassing. Ugly → working → clean. In that order.

## Interview Standard

By the end of this track, you should be able to:

- explain any backend concept from the OS level up
- design systems on a whiteboard with justified tradeoffs
- debug production failures from symptoms to root cause
- discuss consistency, availability, and partition tolerance without hand-waving
- evaluate technology choices with real reasoning, not hype
- build, test, deploy, and operate a backend service end to end
